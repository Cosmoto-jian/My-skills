# 论文解读经验闭环（内容驱动版）

## 目标

把每篇解读中具体的理解、事实、表达和交付教训变为下一次可执行的判断。评价核心是有没有讲清这篇论文，而非是否填满七节、凑够段数、粗体、图片或参考文献。不得把积累的经验固化成另一套论文类型模板。

## 写作前：先读经验

现有脚本入口：`/workspace/My-skills/paper-lesson-loop/scripts/read_lessons.py`。先检查实现和安全配置，再按已有授权运行；默认最近8条，并检查项目最新用户规则。遇矛盾查原始来源、日期及适用分支，不盲目叠加。例如视频中间稿免审不代表公众号免用户终审。

读经验时提取：发生了什么具体偏差、为什么影响理解或结论、如何核验纠正、适用于什么情形。并非所有后台检查都应成为正文栏目。无消融不自动视为缺点；只有影响具体归因的证据缺口才进入边界讨论。

## 写作中：形成可追溯工作底稿

先分析研究问题、贡献、证据、机制、边界，再选栏目和讲述顺序。保留数字核对、图文及rights记录，不要求对外展示全部核查过程。方法解释一次，结果按问题串联；重要边界不因简洁省略，无关细节不因完整塞入。

## 主线、合并表与双轮审核

读经验与全文版本核实 → 内部主线笔记（读者问题/新答案/关键证据）→ 内容决定章节 → 数字核对表整合重要论断证据表 → 成稿 → 第一轮科学审核 → 第二轮读者审核并调用『科研图文表达修订』→ 据证据表回归复核 → 用户终审 → 明确批准后落盘验证 → 记经验。

调用已注册可用的『科研论文解读编排与双轮审核』（ID `skill-1794113977555`）组织上述流程；第二轮调用已注册可用的『科研图文表达修订』（ID `skill-1794113621361`）。两者是可用用户skill，不代表My-skills仓库源已同步。仓库内容驱动结构升级仍因CloudAgent额度限制待实施；仓库外草案未安装。

内部主线笔记只回答三个问题：读者真正关心什么，论文提供了什么新答案，最关键的证据是什么。依据研究问题、贡献、机制和边界决定章节、顺序与篇幅，不按固定节数或论文类型模板填空。

将数字核对表与重要论断证据表整合为一张内部表，只覆盖标题、摘要和正文的重要论断，不给所有句子记账。字段至少为：论断/所在位置、原文小节/页码/图表面板、适用条件、基线、分母与指标、证据类型（计算预测/已有实验再分析/新增实验等）、主张边界及核实状态。没有对应项可注明不适用，不能捏造。核查矛盾与未核实项并如实处理。

第一轮科学审核：既查准确，也查是否讲透；核对重要论断与证据表、数字口径、因果与相关、比较基线、数据划分/泄漏、计算与实验区别、图文对应及影响结论的边界。第二轮读者审核：查难懂或跳步、背景过量、重点分散、重复和可删无关段落，并调用『科研图文表达修订』去报幕、拔高与机械句式。必要解释即使没有新增事实也可保留；摘要与图注独立阅读所需的限定不能为去重删掉。修订保留术语、数字、限定、因果和比较对象，不编造经历、不追求检测分。

修订后依据合并证据表做针对性回归复核，不称为新增第三整轮；若科学主张或其强度、条件、因果归因发生变化，则返回第一轮科学审核。无消融不强设栏目、不自动判缺陷，仅在具体证据缺口影响归因时解释。图注可保留科学出处，不写产权文字；许可授权及商用限制独立记录。

主线笔记、数字与论断合并表、简短审核修正记录均为内部工作材料，不塞入正文，不新增用户中途审批，不做旧稿A/B重写。经验只记录两轮实际发现并修正的偏差；不为每句建账或硬凑每轮条目。

## 验证交付后：写经验

现有脚本入口：`/workspace/My-skills/paper-lesson-loop/scripts/write_lesson.py`。核实其实际参数，不抄旧根目录命令。经验建议覆盖以下维度中的实际新教训，不要求每篇每维度硬凑一条：

1. 理解：是否识别真正问题和贡献；是否混淆互补/替代、预测/机制、计算/实验。
2. 忠实度：数字分母、指标、样本集合、版本、基线、图文和重要限制如何回原文核实。
3. 易读性：采用什么组织顺序帮助读者理解；哪里删掉重复方法或无关栏目，哪里必须保留边界。
4. 表达：术语和公式如何自然解释，如何去掉导航、口号、机械小结而不损失科学限定。
5. 交付：用户终审、明确落盘授权、文件字节/路径核验、独立rights记录及实际故障状态。

一条经验只记一件事，写清情形、原因、纠正措施及适用范围。不要记录“七节齐全所以质量合格”或将示例栏目变为新必填项。

用户终审材料为标题、120字内摘要与主要关键论断，不强制每节一句。用户明确批准落盘后，Mac文件数、字节、图片路径及完整性验证通过，才写实际完成和交付经验；失败如实记待写入/待验证，不记已完成。落盘不是发布，未经准确内容批准不外发。
